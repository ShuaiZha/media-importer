# 日常使用与维护

[文档目录](README.md) · [配置参考](configuration.md) · [备份与恢复](recovery.md)

## 日常操作

1. 保持电脑唤醒、缓存盘可用，启动后台服务。
2. 通过 USB 连接已开机的相机。第一次使用时在飞书核对身份并点击「确认并备份」。同一台相机在服务重启后继续同步，不必再点旧确认卡。
3. 通过「状态」查看进度；需要暂停时使用「同步 → 停止同步」。
4. 按卡片中的相机连接要求操作。导入完成后，电脑与缓存盘仍需可用，直到远端归档及缓存清理完成。

| 飞书操作 | 行为 |
| --- | --- |
| 查看状态 | 当前结论、两路进度、设备与存储、问题及实际归档位置 |
| 开启同步 | 继续当前任务；未确认相机时先要求确认 |
| 停止同步 | 停止两路传输和原片删除，保留任务与完整缓存 |
| 删除原片开关 | 选择保留或完整导入后删除；开启需确认 |

同一已确认连接会继续检测新素材。断开后重连或身份变化时重新确认；服务重启后同一台已确认相机继续同步，旧确认卡无效。重复点击旧确认不会重新开启已停止的同步。限速等低频偏好放在[配置文件](configuration.md)，菜单不承担全部配置。

## 如何理解进度

**导入和上传是两条并行队列，各一次处理一个文件。** 每个文件完整导入后即可上传，下一个文件同时继续导入。

| 状态 | 已完成什么 | 仍需什么 |
| --- | --- | --- |
| 尚未扫描 / 扫描中 | 正在建立本轮清单 | 等待确定文件数，不把 `0/0` 当成完成 |
| 本地导入完成 | 本轮应导入的素材已有完整本地副本或已归档，并经过复查 | 若开启原片删除，还需完成相机清理；连接要求以状态卡为准 |
| 上传字节 100% | 内容已写入 SMB 临时文件 | 核对导入时的 SHA-256、大小与 SMB 身份，再正式改名并保存记录 |
| 归档完成 | SMB 正式文件已核验并记录 | 按设置处理原片，清理对应完整缓存 |
| 已归档 / 缓存待清理 | 远端归档已经完成 | 解决缓存权限或磁盘问题；不会因此重新上传 |

数量以实际文件计，包含选定范围内的主文件及必要附属文件；跳过的关联 LRV/THM 单独说明，不计为归档成功。失败文件不会计入完成。

任务按“一次一清”运行：本轮归档、必要清理和结果处理结束后，移除任务明细，只保留必要去重与恢复依据。状态用于当前任务，不提供长期历史查询或累计统计。需要长期保留结果可保存飞书完成通知。

## 传输与清理规则

### 完整性与归档

导入先写本地临时文件。读取相机数据时计算 SHA-256，确认大小和来源身份并落盘后，把该校验值记入缓存记录。上传时按缓存文件再算一次。两次不一致就停止这一份的归档，保留本地缓存，并清理本次远端临时文件。没有这份校验值的旧缓存仍可上传，此时只做下面的抽样核验。

上传先写唯一的 SMB 隐藏临时文件，核对大小和 SMB 文件身份后，禁止覆盖地改为正式文件名，再保存归档记录并清理缓存。程序不把已归档的视频从 SMB 读回来。

归档使用「目标目录 / 设备名与序列号 / 原文件名」。重名依次追加 `_1`、`_2`；暂停、重启和发布结果待确认时继续使用已分配路径。程序保留正式改名前的依据，处理“服务器已改名但响应丢失”，不会仅凭同名同大小认领文件。是否已经传过，看本机任务记录里的素材身份，不看目的地目录里有没有同名文件。

缓存是否仍是当时导入的那一份，另外用卷、大小、修改时间和少量内容抽样判断。抽样用来发现文件被换成另一份，不能代替上面的整文件 SHA-256。

### 原片删除

默认保留原片。开启后，**一组素材完整导入并持久化即可删除相机原片，不等待 SMB 上传**。删除前再次核对相机、组成员及受保护的副本；删除期间防止并行上传线程过早清理该组缓存。

确认关联但不归档的预览文件，只在所属素材满足保护条件后一并处理。关联不明、源身份变化、删除结果不确定或机型未通过验证时保留并报告。删除失败不阻塞完整缓存上传；已归档素材不会因源清理失败退回“未上传”。

### 停止与中断

- 停止同步取消两路当前传输，并停止新的相机删除。
- 未完成导入文件的临时缓存被清理；未完成上传只清理能确认归属的远端临时文件。
- **没有字节断点续传**：下次从头传该文件；完整缓存和已经归档的文件不重传。
- 离线时无法清理的临时文件登记待处理，恢复后清理。同步关闭时仍可清理这些未完成临时文件，不清空完整缓存。
- 已完整上传、正式改名结果未确认的文件进入归档恢复流程，不当作半文件删除。

## 等待与自动恢复

| 条件 | 导入 | 上传 |
| --- | --- | --- |
| SMB 离线 | 额度内继续缓存 | 等待恢复 |
| 相机断开、录像、忙碌或过热 | 等待相机可用 | 继续上传完整缓存 |
| 缓存额度或可用空间不足 | 等待空间 | 继续上传并释放缓存 |
| 缓存盘不可访问 | 等待原盘 | 等待原盘，不使用替代目录 |
| 单个文件失败 | 单独记录并重试，其他可处理文件继续 | 同左 |

暂时故障按退避规则重试；认证、权限或空间问题需按提示处理。实际传输持续没有活动时，程序取消本次尝试并重建连接；无法退出的工作进程由原生监督进程或 Compose 重启。正常等待和限速不直接视为失活。

## 维护命令

| 目的 | 原生 CLI | Docker Compose |
| --- | --- | --- |
| 后台健康 | `media-importer status` | `docker compose ps` |
| 连接诊断 | `media-importer check` | `docker compose exec backup python3 -m media_importer check --json` |
| 近期日志 | `media-importer logs` | `docker compose logs --tail 100 backup bot` |
| 停止后台 | `media-importer stop` | `docker compose stop` |
| 启动后台 | `media-importer start` | `docker compose up -d --no-build` |
| 更新稳定版 | `media-importer update` | `python3 scripts/manage.py update` |

**停止后台会使飞书机器人离线；停止同步不会。** 重启后台沿用已保存的同步偏好，不应把“服务启动”理解为“自动开启同步”。

原生 `status` 展示部署和健康状态，传输明细在飞书查看。Docker 的完整 JSON 状态命令为 `docker compose exec backup python3 -m media_importer status --json`。诊断会检查缓存可写性及连接，但不能代替真实上传验收。

## 目的地身份

一份任务数据绑定一个逻辑目的地。更换域名、IP、端口或账号后，程序核对已有正式文件的大小和 SMB 身份，确认仍是同一存储后才继续原任务；只读取元数据，不下载视频。

无法确认时提示“目的地身份待核对”，保留任务和缓存。存在待确认的远端发布时，应先恢复原连接完成核验。真正换到另一套存储应使用独立任务和缓存目录，不通过手改数据库强行接管。

## 故障排查

| 现象 | 下一步 |
| --- | --- |
| 相机仅充电、不可访问 | 检查数据线、相机开机状态和 USB 网络接口，见[兼容性](compatibility.md#usb-连接要求) |
| 相机已发现但不导入 | 检查飞书设备确认、同步开关、录像或忙碌状态 |
| 缓存空间不足 | 核对缓存额度与磁盘预留；恢复上传或调整限额，不删除未归档完整缓存 |
| macOS 原生后台等待磁盘 | 确认原盘挂载，并允许系统提示的可移动卷访问权限 |
| Docker 挂载失败 | 核对三个目录与 `.env` 已存在，外接盘在线且 Docker 有访问权限 |
| 宿主机可连，容器不可连 | 在容器执行 `check --json`，检查 Docker 网络、VPN 路由和防火墙 |
| SMB 域名间歇失败 | 区分 DNS、TCP 与 SMB 认证；核对宿主机及实际运行环境的 DNS / 代理 / VPN，不盲目更换目的地 |
| SMB 已连接但无法归档 | 核对共享、子目录、剩余空间及创建、改名、删除临时文件权限 |
| 完整缓存待核验 | 保留文件及 `.receipts/`，不要删除重下；见[恢复指南](recovery.md#完整缓存恢复) |
| 提示缓存与导入校验不一致 | 这一份没有归档。保留缓存；相机上仍有原片时再导入这一份，不要删掉唯一副本 |
| 飞书无回复或无提醒 | 检查本人 Open ID、发布、消息事件、卡片回调及通知开关，见[飞书排障](feishu.md#常见问题) |
| 更新失败 | 保留错误与快照，按[原生](native.md#更新)或[Docker](deployment.md#更新稳定版)说明排查，不覆盖任务数据库 |

提交 Issue 时附上版本、系统架构、部署方式、相机型号与固件、脱敏错误及复现步骤。不要上传 `.env`、真实 JSON、SQLite、备份包或素材。
