# 使用与排障

[文档目录](README.md) · [配置参考](configuration.md) · [迁移与恢复](recovery.md)

## 日常操作

1. 保持电脑唤醒、缓存盘可用，通过 USB 连接已开机的相机。
2. 在飞书确认卡核对身份，点击「确认并备份」。
3. 查看「状态」；需要暂停时选择「停止同步」。

同一已确认连接会继续检测新素材。服务重启后，身份复核通过即可继续；检测到断开后重连或身份变化，需要重新确认。旧确认卡不能重新批准。相机连接要求以状态卡为准；导入结束后，电脑和缓存盘仍需保持可用，直到归档与清理结束。

| 飞书命令 | 行为 |
| --- | --- |
| `查看状态` | 当前结论、两路进度、问题与实际归档位置 |
| `开启同步` | 继续任务；来源尚未确认时先要求确认 |
| `停止同步` | 停止两路传输和新的原片删除，保留任务与完整缓存 |
| `删除原片开关` | 保留或完整导入后删除；开启需确认 |
| `素材范围` | 全部 / 视频 / 照片；已开始的传输继续完成 |
| `预览文件` | 是否归档关联 LRV、THM；本轮沿用扫描时设置 |
| `自动通知` | 自动进度、完成和异常提醒；不影响手动查询 |

飞书操作写入 JSON；连接、凭据和低频参数见[配置参考](configuration.md)。

## 进度与完成

导入和上传各一次处理一个文件。**A 完整导入即可上传，B、C 继续导入，无需等整批完成。**

| 状态 | 含义 |
| --- | --- |
| 尚未扫描 / 扫描中 | 文件总数尚未确定，不表示完成 |
| 本地导入完成 | 本轮应导入文件已完整缓存或归档，并通过清单复查；原片清理可能仍待处理 |
| 上传字节 100% | 内容已写入临时文件，仍需校验、正式改名与记录 |
| 归档完成 | 正式文件已核验并记录 |
| 已归档 / 缓存待清理 | 归档成功，缓存清理待恢复；不会因此重新上传 |

数量按实际文件统计，失败文件不计完成，跳过的关联预览文件单独说明。整轮归档和必要清理结束后自动清除任务明细，仅保留去重信息和待发送结果；没有历史查询或累计统计。长期结果可保留飞书完成通知。

## 传输与清理规则

### 完整性与归档

1. 导入写本地临时文件，同时计算 SHA-256；大小、来源身份核对并落盘后，登记完整缓存。
2. 上传时顺序读取缓存并再次计算 SHA-256，不一致则停止该文件，保留缓存。
3. 上传写唯一 SMB 隐藏临时文件，核对大小和文件身份，再禁止覆盖地改名。
4. 保存归档结果后清理对应缓存。**不完整读回 SMB 视频。**

旧缓存没有导入流校验值时仍可处理。卷标识、大小、修改时间和少量内容抽样用于确认缓存身份，不能替代整文件校验。

归档路径为「目标目录 / 设备名与序列号 / 原文件名」。重名不区分大小写，依次加 `_1`、`_2`；分配后的路径持久化。正式改名响应丢失时根据发布依据恢复，不能仅凭同名同大小认领文件。去重依据为素材身份与本机记录。

### 原片删除

默认保留原片。开启后，整组应保护的素材完整导入并持久化即可清理相机，**不等待远端归档**；期间缓存可能是唯一副本。

删除前复核设备、组成员及完整副本，删除期间保护组内缓存。跳过归档的关联预览文件，仅在所属素材满足保护条件后清理。关联不明、身份变化、结果不确定或机型未通过删除验证时保留并报告。

删除失败不阻塞缓存上传，也不让已归档状态倒退。关闭删除后，旧删除错误不再阻止已归档且缓存已清理的素材收尾；结果尚未确认的删除仍需核实。

### 停止与中断

没有字节断点续传，中断文件下次从头传；完整缓存和已归档文件不重复传输。程序只清理能确认归属的半文件，离线时登记待清理，恢复后继续。同步关闭仍可清理这些临时文件，不清空完整缓存。

已经完整上传、正在确认正式改名结果的文件进入归档恢复，不作为半文件删除。

## 自动恢复与等待

| 情况 | 导入 | 上传 |
| --- | --- | --- |
| SMB 离线 | 缓存额度内继续 | 等待恢复 |
| 相机断开、忙碌、录像或过热 | 等待来源可用 | 继续完整缓存 |
| 缓存额度或磁盘预留不足 | 等待空间 | 继续上传释放空间 |
| 缓存盘不可访问 | 等待原盘 | 等待原盘，不切换替代目录 |
| 单个文件失败 | 单独退避重试，其他可处理文件继续 | 同左 |

传输持续无活动时取消本次尝试并重连；无法退出的工作进程由原生监督进程或 Compose 恢复。正常等待和限速不直接视为失活。

### 目的地身份

一份任务绑定一个逻辑目的地。更换域名、IP、端口或账号后，程序读取已有归档的大小与 SMB 身份，确认仍是同一存储后继续。无法确认则保留任务与缓存，提示核对；有待确认发布时先恢复原连接。换成另一套存储应使用独立数据目录，不修改数据库强行接管。

## 故障排查

先检查后台与日志：[原生命令](native.md#常用命令) / [Docker 命令](deployment.md#管理服务)。停止后台会使机器人离线，停止同步不会。

| 现象 | 下一步 |
| --- | --- |
| 相机仅充电或不可访问 | 检查数据线、开机状态、USB 网络接口，见[连接要求](compatibility.md#usb-连接要求) |
| 发现相机但不导入 | 检查设备确认、同步开关、忙碌与录像状态 |
| 缓存空间不足 | 区分额度与磁盘预留；恢复上传或调整限制，保留未归档缓存 |
| macOS 等待磁盘 / Docker 挂载失败 | 确认原盘、目录和访问权限 |
| 宿主机可连，容器不可连 | 在容器运行 `check --json`，核对 DNS、VPN 路由与防火墙 |
| SMB 间歇失败或不能归档 | 区分 DNS、网络、认证、权限和容量；账号需能创建、改名及删除临时文件 |
| 完整缓存待核验或校验不一致 | 保留文件、`.receipts/` 和快照，按[恢复指南](recovery.md#完整缓存恢复)处理，不删除唯一副本 |
| 飞书无回复或无通知 | 检查身份、发布、订阅和通知开关，见[飞书排障](feishu.md#常见问题) |
| 更新失败 | 保留错误与维护快照，不用旧数据库直接覆盖新任务 |

提交 [Issue](https://github.com/ShuaiZha/media-importer/issues) 时提供版本、系统架构、部署方式、型号与固件、脱敏日志及复现步骤。
