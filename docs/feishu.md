# 飞书应用机器人

[文档目录](README.md) · [配置参考](configuration.md) · [日常使用](operations.md)

使用**企业自建应用机器人、长连接、本人单聊**完成控制与通知。原生 CLI 和 Docker 共用此接入方式，无需群机器人 Webhook、公网回调地址或端口映射。同一应用只运行一个机器人实例。

配置顺序：**创建应用与凭据 → 启动本机服务 → 配置订阅和菜单 → 发布 → 验证**。

## 1. 创建应用与获取凭据

1. 登录[飞书开发者后台](https://open.feishu.cn/app)，在所在组织创建「企业自建应用」，例如「素材导入助手」。需要组织允许创建和发布应用。
2. 在「添加应用能力」中添加「机器人」。
3. 在「凭证与基础信息」取得 App ID、App Secret，稍后填入安装向导；已有部署则保存在本机 `.env`。
4. 在「权限管理」按标识开通以下**应用身份权限**：

| 权限 | 用途 |
| --- | --- |
| `im:message:send_as_bot` | 发送通知、更新机器人自己发送的卡片 |
| `im:message.p2p_msg:readonly` | 接收本人单聊文字和菜单消息 |

获取**本人在当前应用中的 Open ID**：

1. 打开 [API 调试台](https://open.feishu.cn/api-explorer)，确认选中刚创建的应用。
2. 选择「消息 → 消息管理 → 发送消息」，接口为 `POST /open-apis/im/v1/messages`。
3. 将 `receive_id_type` 设为 `open_id`，点击「快速复制 open_id」，选择自己。
4. 将得到的 `ou_...` 用作向导中的本人 Open ID，或 `.env` 的 `FEISHU_OWNER_OPEN_ID`；仅获取 ID，无需点击发送消息。

```dotenv
FEISHU_APP_ID='cli_EXAMPLE00000000'
FEISHU_APP_SECRET='REPLACE_WITH_APP_SECRET'
FEISHU_OWNER_OPEN_ID='ou_EXAMPLE00000000'
```

三个值都需替换。Open ID 与应用绑定，不能使用其他应用的 Open ID、组织 `user_id` 或群 `chat_id`。程序只接受配置的本人操作，不会自动绑定第一个发消息的人。

## 2. 启动本机服务

按[原生 CLI](native.md)或[Docker Compose](deployment.md)完成安装与连接配置，选择其中一种运行。

原生版检查：

```sh
media-importer status
media-importer logs
```

Docker 版检查：

```sh
docker compose ps
docker compose logs --tail 100 bot
```

程序使用内置的飞书官方 SDK 建立长连接，无需另跑 SDK 示例。保持本地服务在线，再到后台保存订阅。如果提示“应用未建立长连接”，先核对 App ID/Secret、机器人健康状态与网络。参见[官方长连接说明](https://open.feishu.cn/document/server-docs/event-subscription-guide/event-subscription-configure-/request-url-configuration-case)。

## 3. 配置事件与卡片回调

在应用「事件与回调」中分别设置：

| 页签 | 接收方式 | 订阅 |
| --- | --- | --- |
| 事件配置 | 使用长连接接收事件 | 接收消息：`im.message.receive_v1` |
| 回调配置 | 使用长连接接收回调 | 卡片回传交互：`card.action.trigger` |

两处均保存。消息事件用于文字与菜单，卡片回调用于刷新、设备确认和原片删除确认，不能互相替代。长连接不填写请求 URL、Verification Token 或 Encrypt Key。

## 4. 创建菜单

在「机器人 → 机器人自定义菜单」启用菜单，选择可切换菜单，并默认展示菜单。按下表建立三个主菜单、四个操作：

| 主菜单 | 子菜单 | 叶子菜单动作 |
| --- | --- | --- |
| 状态 | 查看状态 | 发送文字消息：`查看状态` |
| 同步 | 开启同步 | 发送文字消息：`开启同步` |
| 同步 | 停止同步 | 发送文字消息：`停止同步` |
| 原片处理 | 删除原片开关 | 发送文字消息：`删除原片开关` |

所有叶子菜单使用**发送文字消息**，不选「推送事件」，不需要额外订阅自定义菜单事件。操作与输入同名文字等效，用户无需记住命令。更多后台界面说明见[官方菜单指南](https://open.feishu.cn/document/client-docs/bot-v3/bot-customized-menu)。

菜单保留高频操作；限速、缓存额度、素材类别、预览文件与通知偏好在 [`settings.json`](configuration.md#settingsjson日常偏好) 中修改。

## 5. 发布应用

1. 在「版本管理与发布」创建版本，填写版本号及说明。
2. 将应用可用范围限定为本人，完成发布；组织要求审核时需管理员批准。
3. 在飞书客户端搜索应用名并打开机器人单聊。

保存草稿不等于发布。权限、订阅或菜单修改后需发布生效；菜单可能稍后刷新，重新进入会话，或先发送 `状态` 验证。迁移电脑并沿用同一应用时，不用重新创建菜单。

## 6. 验证与启用通知

首次保持同步关闭、原片保留，依次检查：

1. 「查看状态」返回综合状态卡，包含两路进度、连接要求、缓存与目的地状态。
2. 「刷新状态」更新原卡片，时间为北京时间。
3. 「删除原片开关」显示当前策略；开启删除需要确认，不会仅因打开设置卡就删除。
4. 连接相机，核对确认卡中的身份、兼容状态与原片策略，点击「确认并备份」。

**开启同步会处理当前范围内的全部待导入素材和完整缓存，菜单不支持单选文件测试。** 首次验收应使用只含少量测试素材的设备，保留原片。

在 JSON 中将 `notifications.enabled` 设为 `true`，即可接收自动通知。默认每 5 分钟更新进度卡，间隔可配置。设备确认卡、手动查询和控制回执不依赖此开关。

| 消息 | 含义 |
| --- | --- |
| 状态 / 进度 | 两路分别显示进度、完成数量、当前文件和必要等待原因；自动进度更新同一张卡 |
| 本地导入完成 | 本轮已完整导入、相机连接要求和仍待归档数量；不代表远端完成 |
| 归档完成 | 归档文件数量、容量、原片及缓存处理结果、实际归档位置 |
| 失败 / 恢复 | 问题、影响和处理建议；同一持续故障不重复刷屏 |
| 相机确认 / 断开 | 设备身份及本次确认；断开后完整缓存仍可上传 |

所有消息时间使用北京时间。相机断开后重连，或型号、固件、序列号变化时，需重新确认。服务重启后同一台已确认相机继续同步，旧确认卡不能再批准。`notifications.connection_events` 控制断开提醒；普通逐文件日志保留在本机。

## 常见问题

| 现象 | 检查 |
| --- | --- |
| 搜不到机器人 | 机器人能力、应用发布状态、本人可用范围、客户端所在组织 |
| 后台无法保存长连接 | 本地 `bot` 是否运行，App ID/Secret 是否属于此应用，网络能否访问飞书 |
| 菜单不显示或仍是旧版 | 是否已发布，重新进入会话；先发 `状态` 排除菜单刷新延迟 |
| 菜单无回复 | 动作是否为发送文字消息，消息权限与 `im.message.receive_v1` 是否生效，Owner Open ID 是否正确 |
| 卡片不能确认或刷新 | `card.action.trigger` 是否配置并发布；重新获取卡片，避免使用旧操作 |
| 能查状态但无自动提醒 | `notifications.enabled` 默认关闭；检查本地日志中的发送错误 |
| 设备或存储异常 | 按状态卡提示处理，见[排障表](operations.md#故障排查) |

排障日志对外分享前需脱敏，不公开真实 App Secret、Open ID、SMB 密码、数据库或私人素材。
