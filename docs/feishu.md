# 飞书应用机器人配置

[返回首页](../README.md) · [部署与配置](deployment.md) · [使用与维护](operations.md)

本项目通过**企业自建应用机器人 + 长连接 + 本人单聊**提供控制和通知。无需群机器人 Webhook、签名密钥、公网回调地址或端口映射。容器主动连接飞书，电脑必须保持联网与唤醒。同一应用只运行一个 `bot` 服务。

## 1. 创建应用并获取凭据

1. 登录 [飞书开发者后台](https://open.feishu.cn/app)，选择自己所在的组织，创建「企业自建应用」。应用名可用「素材导入助手」。需要有创建、发布应用的权限；若组织要求审核，由管理员批准。
2. 在「添加应用能力」中添加「机器人」。不需要创建网页应用或配置网页首页。
3. 在「凭证与基础信息」找到 **App ID** 和 **App Secret**，填入本机 `.env`，不要发到聊天或提交仓库。
4. 在「权限管理」中仅开通以下**应用身份权限**；使用权限标识搜索，避免选错同名项。

| 权限标识 | 本项目用途 |
| --- | --- |
| `im:message:send_as_bot` | 机器人给本人发送消息，并更新自己发送的卡片 |
| `im:message.p2p_msg:readonly` | 读取本人发给机器人的单聊文字和菜单消息 |

本项目不读取群历史、全量通讯录或云文档，也不使用 CardKit 卡片实体接口。不要直接导入其他项目的一大批权限。

**获取当前应用中的本人 Open ID：**

1. 打开 [API 调试台](https://open.feishu.cn/api-explorer)，确认左上角选中刚创建的应用；如不符，点击「切换应用」。
2. 搜索并选择「消息 → 消息管理 → 发送消息」接口（`POST /open-apis/im/v1/messages`）。
3. 将查询参数 `receive_id_type` 选为 `open_id`，点击出现的「快速复制 open_id」。
4. 在人员选择器中选择自己，复制以 `ou_` 开头的 ID，写入 `FEISHU_OWNER_OPEN_ID`。这里只取 ID，**无需点击「开始调试」发送消息**。

Open ID 与应用绑定。同一个人在其他应用里的 Open ID、组织的 `user_id`、群聊 `chat_id` 都不能替代它。应用发布时也要将本人加入可用范围。

`.env` 示例，三个值均需替换：

```dotenv
FEISHU_APP_ID='cli_EXAMPLE00000000'
FEISHU_APP_SECRET='REPLACE_WITH_APP_SECRET'
FEISHU_OWNER_OPEN_ID='ou_EXAMPLE00000000'
```

程序只接受这个 Open ID 在本应用中的单聊和卡片操作，所有通知也只发送给该人。不会把第一个发消息的人自动绑定为所有者。

## 2. 先启动本地长连接

回到 [首次部署指南](deployment.md#首次部署)，填好相机、SMB、挂载路径，创建配置文件及目录，保持同步、删除原片和自动通知均关闭。然后运行：

```sh
docker compose config --quiet
python3 scripts/build.py
docker compose run --rm --no-deps backup validate
docker compose up -d --no-build
docker compose ps
docker compose logs --tail 100 bot
```

`bot` 使用已集成的飞书官方 SDK 建立长连接，不需要再运行官方示例程序。连接成功后才回后台保存下一步配置。日志会隐藏签名连接地址和凭据；以 `bot` 的健康状态及后台能否保存长连接为准。参见 [官方长连接配置顺序](https://open.feishu.cn/document/server-docs/event-subscription-guide/event-subscription-configure-/request-url-configuration-case)。

若后台说“应用未建立长连接”，先检查 Docker 是否运行、`bot` 是否重启/不健康、`.env` 中 App ID/Secret 是否正确，以及容器能否访问飞书。修改 `.env` 后执行 `docker compose up -d --force-recreate`，再保存订阅。

## 3. 配置事件与卡片回调

进入应用的「事件与回调」，分别配置两个页签：

| 页签 | 接收方式 | 添加的事件或回调 |
| --- | --- | --- |
| 事件配置 | 使用长连接接收事件 | 接收消息：`im.message.receive_v1` |
| 回调配置 | 使用长连接接收回调（界面也可能写作接收事件） | 卡片回传交互：`card.action.trigger` |

两处都保存。消息事件让文字指令与菜单生效；卡片回调让「刷新」、保存设置和删除确认生效。**卡片回调在“回调配置”中添加，不能用消息事件替代。** 长连接模式无需填写请求 URL、Verification Token 或 Encrypt Key。

项目的菜单使用“发送文字消息”，不使用“推送事件”，因此不需要订阅机器人自定义菜单事件。

## 4. 创建三组菜单

在「机器人 → 机器人自定义菜单」开启菜单，展示样式选「可切换菜单」，默认展示选「菜单」。创建以下层级：

```text
状态
├── 运行总览
├── 设备与存储
└── 归档结果
同步
├── 开启同步
└── 停止同步
设置
├── 传输设置
├── 原片处理
├── 通知设置
└── 使用帮助
```

三个一级菜单用于展开子菜单。**九个叶子菜单的响应动作全部选择「发送文字消息」**；飞书会把菜单名称作为指令发送，因此请逐字使用上述名称，不加图标、空格或其他前后缀。不要选择“跳转链接”或“推送事件”。

| 入口 | 卡片内容与操作 |
| --- | --- |
| 状态 → 运行总览 | 能否拔相机、需要处理的问题、两路进度条和等待原因 |
| 状态 → 设备与存储 | 相机健康、缓存额度/空间、SMB 状态；连接详情展开身份、路径和自检 |
| 状态 → 归档结果 | 本轮/历史结果与实际归档目录、清理结果；文件详情展示重名后的文件名 |
| 同步 → 开启同步 / 停止同步 | 控制两路传输；停止后保留完整缓存，未完成文件下次从头传输 |
| 设置 → 传输设置 | USB 直连／手动 Wi-Fi、同步内容（全部／视频／照片）、上传限速、缓存额度、磁盘预留，保存到 JSON |
| 设置 → 原片处理 | 默认保留原片；开启删除需经过单独确认卡 |
| 设置 → 通知设置 | 连接提醒与传输通知各自开关、进度间隔（60–86400 秒，默认 300 秒）、消息前缀 |
| 设置 → 使用帮助 | 菜单和使用流程说明 |

可切换菜单最多 3 个主菜单、每项最多 5 个子菜单；本配置在限制内。“发送文字消息”动作要求飞书客户端 7.22 及以上。参见 [官方菜单使用指南](https://open.feishu.cn/document/client-docs/bot-v3/bot-customized-menu)。

## 5. 发布并打开机器人单聊

1. 在「版本管理与发布」创建版本，填写版本号与说明。
2. 将可用范围限定为本人；不需要对外部用户或群开放。
3. 提交并完成发布，若需要管理员审核则等待通过。只保存草稿不会让权限、菜单和订阅全部生效。
4. 在飞书客户端搜索应用名，打开机器人单聊。菜单发布后可能延迟约 5 分钟，届时退出会话再进入；也可先切回输入框发送 `运行总览`。

菜单配置保存在飞书应用后台。克隆仓库不会自动生成菜单；迁移电脑并沿用同一应用时，菜单无需重建。之后修改菜单或权限也要重新发布版本。

## 6. 验证交互与通知

先在同步关闭、原片保留状态下验证：

1. 分别点击三个状态子菜单，应返回不同内容的卡片。
2. 所有消息时间应显示北京时间。点击每张卡片的「刷新」，应在**原消息**上更新查询时间，不另发一张。菜单再次点击会发送新的查询快照。
3. 打开「设置 → 传输设置」「原片处理」「通知设置」，核对当前值；仅打开卡片不会开启传输或清理。
4. 若需要区分“收不到控制指令”和“发不出消息”，本机运行 `docker compose exec bot python3 -m media_importer bot-panel`，这会主动向配置的本人发送一张状态卡。

现有菜单无需新增层级：运行总览在同步开启时提供「传完当前文件再停」；设备与存储提供「检查连接」；有异常时提供分页列表，完整缓存待核验时提供「核验缓存」。核验要求先停止同步，检查和核验结果更新原回执，且不会删除素材。

连接提醒默认开启，停止同步时仍能收到。相机身份核对成功后提醒已连接；连续 3 次不可访问且持续至少 20 秒后提醒断开，短暂超时不刷屏。提醒指所选链路不可访问，不代表能确定物理拔线。初次启动没有相机时不发送断开消息；相同状态和重启不重复发送。连接提醒可以单独关闭。

传输通知默认关闭。需要进度及结果提醒时，在「设置 → 通知设置」开启传输通知，再开启同步：

- 开启同步后通常 5 秒内发送进度卡，即使尚未扫描也显示等待状态；网络故障会重试。
- 同一批次后续按设置间隔更新同一张进度卡；两条进度分别代表相机导入、本地缓存到 SMB 归档。
- 导入完成可拔相机、正式归档完成、需要处理的失败分别发提醒；普通逐文件日志不刷入单聊。
- 关闭传输通知仍可通过菜单查询和控制。停止同步后，已有进度卡会结束运行显示，连接提醒继续工作。
- 缓存连续 6 小时没有新上传进展时提醒一次，展示尚未归档数量及相机原片已清理数量；同步关闭时不发送。确认故障恢复后更新原问题卡。

测试只使用小素材和独立目的地，保持原片保留；开启同步会处理绑定相机中所选类别的待导入素材及已有完整缓存，不能在菜单里只选一个文件。默认选择全部素材。测试完成后点「同步 → 停止同步」。

## 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 搜不到机器人 | 是否添加机器人能力、发布成功、本人在可用范围内、客户端处于同一个组织 |
| 有输入框但没有菜单 | 是否在本应用配置并发布菜单；等约 5 分钟并重新进入会话；检查客户端版本与菜单/输入框切换按钮 |
| 菜单出现但点击无回复 | 叶子菜单动作必须为“发送文字消息”，名称必须匹配；检查消息权限、`im.message.receive_v1`、`bot` 健康状态和当前应用的本人 Open ID |
| 能收到卡片但刷新或保存无效 | 检查“回调配置”的长连接及 `card.action.trigger`，发布后从菜单获取新卡；旧卡超过有效期须重新获取 |
| 能查状态但没有自动进度 | 默认传输通知关闭；在通知设置中开启，进度按间隔更新原卡，完成与失败另发 |
| 提示仅本人可操作 / 接收人不可用 | 重新在当前应用的 API 调试台复制本人 Open ID；核对应用可用范围，不要换成群 ID 或其他应用的 ID |
| `bot` 长时间不健康 | `docker compose logs --tail 100 bot`；核对凭据和容器网络；修改 `.env` 后重建容器 |
| 状态卡显示缓存盘或 SMB 不可用 | 在「设备与存储」查看具体原因；能收消息只说明飞书链路可用，传输连接需分别排查 |

排障时保留本机配置、数据库和完整缓存。不要把 `.env`、带凭据的终端输出或包含个人路径的截图直接贴到公开 Issue。
