## 当前支持

v1.0.0 主要实机验证组合为 **Mac Apple Silicon + HERO9 Black（HD9.01.01.72.00）+ SMB**。构建、隔离测试和真实设备验证分别记录；未验证机型不因构建通过而获得删除能力。有声 RTMP 直播保留为实验功能。

| 环节 | 已实现 | 范围 |
| --- | --- | --- |
| 来源 | GoPro USB / Wi-Fi 网络 | 每个实例一台设备；无线限 Mac 原生版 |
| 拍摄 | 录像、拍照、延时、预设与参数、定长录像、HiLight | Mac 原生无线连接；可用参数由相机返回 |
| 实时预览 | H.264，优先 WebRTC，MSE / 原生 HLS 回退 | 服务端：Mac 原生版、HERO9 Black；客户端见下方验收范围 |
| 有声直播（实验） | RTMP H.264 + AAC，浏览器音频使用 Opus | Mac 原生版、HERO9 Black；家庭 Wi-Fi 或已开启的 Mac 热点；不同时进行拍摄控制 |
| 相机页面 | 取景与拍摄控制、缩略图、单个视频回放 | Mac 原生版；回放优先使用关联 LRV，原 MP4 的编码兼容性由观看端决定，照片显示缩略图 |
| 目的地 | SMB | 一个共享目录，可为 NAS 或电脑共享 |
| 控制与通知 | 飞书应用机器人 | 本人单聊 |

通用架构不等于已适配所有相机。其他品牌与其他存储协议尚未接入。

## GoPro

适配按型号与固件判断，不限定某台设备的序列号。

| 型号 / 固件 | 导入与归档 | 原片删除 |
| --- | --- | --- |
| HERO9 Black · `HD9.01.01.72.00` | macOS 实测视频、分段视频、照片及附属文件 | MP4 与关联 LRV；v1.0.2 增加普通单张 JPG 无线清理。连拍、RAW、THM 继续保留 |
| HERO9 其他固件；HERO10 / 11 / 12 / 13 Black；HERO11 Black Mini | 使用通用 HTTP 接口，允许确认后导入；待实机验证 | 强制保留，即使开启删除开关 |
| 其他或无法识别型号 | 仅展示身份，不开放导入 | 不开放 |

设备名使用实际识别结果。HERO9 的分段组合与部分 MP4 元数据补读保留在适配器中，官方接口支持不代替实机验收。

HERO9 重启后可能改变媒体接口报告的创建时间。适配器通过有限范围读取 MP4 文件头核对稳定时间与 GUMI，避免重复归档；关联 LRV、THM 使用主文件的稳定时间。头部缺失或身份不一致时保留素材并报错。此修正尚未扩展到其他型号或照片格式。

### USB 连接要求

- 相机开机，使用支持数据传输的 USB 线。
- 系统生成 USB 网络接口，运行环境能访问相机 HTTP 服务；仅充电或 MTP 不满足条件。
- Docker 通过网络读取，不使用 USB 直通。

JSON `source_options.url` 和 `source_options.serial` 可留空自动发现。GoPro 地址通常由序列号末三位 `XYZ` 推导为 `http://172.2X.1YZ.51:8080`，例如 `789` 对应 `http://172.27.189.51:8080`。这是相机地址，最终以身份探测结果为准。

不保证插线自动开机，电脑需保持唤醒。首次[飞书确认](operations.md#日常操作)不可由地址或序列号提示代替。已确认设备按适配器类型与完整序列号识别，重连或换链路无需再次确认；其他设备仍需确认。上一台设备仍有未完成传输或待确认清理时，不能直接切换。

## 无线连接与拍摄控制

以下能力需要 **v0.11.0+ 的 Mac 原生版**：

- Mac 原生后台通过蓝牙识别已确认相机，开启热点并连接 Wi-Fi；不需要另装 App。
- 自动连接要求 Mac 有独立的有线上网链路，Wi-Fi 专门连接相机。缺少有线链路时不会自动抢占唯一网络；也可先手动连接热点。
- 相机保持开机、开启无线连接，可接独立充电器。USB 数据模式通常限制拍摄控制；拍摄功能只在无线连接可用时提供。
- 首次蓝牙配对或 macOS 蓝牙权限仍需本人完成；不要让手机 Quik 同时控制相机。
- `auto` 优先 USB；无线导入中出现 USB 时，等当前文件边界再切换。热点连接失败按间隔重试，不根据系统命令返回码判断成功。
- HERO9 `HD9.01.01.72.00` 支持经副本核验的 MP4 与关联 LRV 无线清理；v1.0.2 增加普通单张 `GOPRnnnn.JPG`。连拍、RAW、THM、其他型号与固件仍保留；USB 删除继续受上表约束。单个成员不受支持时保留整个关联范围，不先删除主文件。
- 不切回家庭 Wi-Fi；Windows、Linux、Docker 本轮保留 USB。

HERO9 已实测无线重连、并行导入 / 上传，以及飞书录像、拍照、延时、预设与参数读写、15 秒定长录像和 HiLight；拍摄后确认导入已用小照片验证。详细验收范围见 [v0.11.0](releases/v0.11.0.md)。其他型号仅开放接口声明的能力，仍待硬件验证。

## 实时预览

服务端仅开放 HERO9 Wi-Fi，由 Mac 原生后台管理内置 go2rtc；USB、其他机型和其他服务端系统待验证。支持持续预览和 Tailscale 私有 HTTPS/WSS，不提供公网匿名观看或录像存档。

Mac 飞书、Mac 浏览器与 Safari 已验证 WebRTC 直接解码，无需转码。用户在 iPhone 飞书使用移动网络与 Tailscale，确认 WebRTC 连续播放，观察到的延迟由原先 2–4 秒降至 1 秒以内；这是该环境下的实测反馈，不是所有网络的延迟保证。

统一相机页面已在 Mac 飞书验证参数读写、缩略图、单个视频回放及预览与录像启停。iPhone 飞书已验证素材页、回放、勾选、备份确认和清理预览取消；手机参数修改与实际删除未在本轮重复执行。入口及回放限制见[相机页面](feishu.md#相机页面)。

兼容路径保留 MPEG-TS HLS / MSE：Mac Safari 与 iPhone 飞书已验证 HLS 出画；Mac 飞书已验证 MSE，用户确认外网 Windows 飞书能出画。初测的 Apple 黑屏由 fMP4 初始化参数不匹配引起，切换 MPEG-TS HLS 后恢复。其他客户端、长期播放与网络恢复仍须分别验证。旧版“60 秒无人观看结束”已移除，主动停止和源故障回收仍保留。使用方法见[实时预览](feishu.md#实时预览)。

## 平台

| 平台 | 原生包 | 验证范围 |
| --- | --- | --- |
| macOS Apple Silicon | ARM64 | 原生 / Docker、后台、飞书、HERO9 → 缓存 → SMB 实测 |
| macOS Intel | AMD64 | 构建与隔离安装测试；设备链路待验证 |
| Linux | ARM64 / AMD64 | 构建与隔离安装测试；实际后台、USB 链路待验证 |
| Windows x64 | AMD64 | 构建、隔离安装、更新、卸载与占用恢复测试；实际后台、USB 链路待验证 |

Docker 镜像为 Linux ARM64 / AMD64；Windows ARM 原生包暂不提供。构建通过不等于硬件兼容。

原生后台在用户登录后启动，不负责自动唤醒。Linux 无 systemd 用户会话时可使用 `media-importer run` 或 Docker。macOS 原生包尚未进行 Developer ID 公证。

## 存储与网络

- SMB 共享与目标子目录需存在，账号具备列目录、读写、创建、改名和删除临时文件权限。
- IP、域名和经 VPN / Tailscale 的远程访问均可使用，需从实际运行环境验证。
- 缓存可在内置盘或外接 SSD；原盘不可访问时等待，不另找替代盘。
- 飞书使用主动长连接，无需公网入口；同一应用不能由多台电脑同时运行。

首次验证使用少量素材并保留原片。开启备份处理配置范围内的全部待导入素材及完整缓存，需要指定文件时，停止全量备份后使用「选择文件」。

### 有声直播验收（实验功能）

2026-10-23：HERO9 Black 经 Mac 临时热点向原生程序推送 H.264 720p 与 AAC 音频；Mac 飞书通过 WebRTC 连续播放，Opus 音频实际解码通过。结束直播后原拍摄参数与相机热点恢复，关闭 Mac 热点后重新连接相机，并复验原无声预览。相机 17 个文件未变，未启用存储卡录制或原片删除。

Mac 当时有独立有线网络；完全离线、iPhone 有声播放及兼容播放模式尚未实机验收。首次蓝牙准备曾失败，重试成功；程序提供有界等待、阶段提示与停止恢复，不承诺每次首次连接必然成功。
