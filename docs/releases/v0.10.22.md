# v0.10.22 · 设备适配边界与 Windows 卸载恢复

[版本列表](../README.md#版本说明) · [GitHub Release](https://github.com/ShuaiZha/media-importer/releases/tag/v0.10.22)

## 设备适配

设备发现、型号能力、专用文件格式、保活与超时策略统一由来源适配器负责。通用流程处理导入、归档和通知，不再直接依赖 GoPro 的规则。

- 设备确认同时核对来源类型和序列号，避免不同来源误用未完成任务。
- 删除关联由适配器声明，范围须在已核验素材组内；保留逐文件删除结果与身份检查。
- GoPro 素材身份、平铺归档路径和现有配置保持不变。当前仍只提供 GoPro USB 来源、SMB 目的地和飞书单聊；HERO9 已实测，其他机型与品牌的支持范围见[兼容性说明](https://github.com/ShuaiZha/media-importer/blob/v0.10.22/docs/compatibility.md)。

## Windows 卸载恢复

彻底卸载在程序退出后等待文件占用释放，最多重试 30 秒。仍被占用时保留命令入口和恢复记录，解除占用后可重试清理，无需重新安装。普通卸载继续保留数据。本次更新不会执行任何卸载操作。

## 更新与验证

原生安装执行 `media-importer update`；Docker 部署执行 `python3 scripts/manage.py update`。更新保留配置、未完成任务、去重信息和完整缓存；JSON 4 / SQLite 5 格式不变，不修改已归档文件。

提供 macOS ARM64 / AMD64、Linux ARM64 / AMD64、Windows AMD64 原生安装包，以及 `ghcr.io/shuaizha/media-importer:0.10.22` 双架构镜像。

测试覆盖独立来源适配器、小文件导入与归档、删除关联与设备确认，以及 Windows 文件占用释放和恢复清理。发布流程对五种平台执行打包后的安装、更新及隔离卸载测试；Windows、Linux 的真实相机链路仍需实机验收。

安装包与镜像不包含真实凭据、运行配置、数据库、素材缓存或本机备份。
